# DeepSeek 实际调用与恢复验证

本轮使用本机已配置的 DeepSeek 接口与 `deepseek-flash`。验证不读取或导出密钥，真实材料、图片、响应、账本和完整报告均仅存本机忽略目录。本文件只记录不含聊天内容的验收结果。

## 小样本：真实请求，受控本地故障

合成案例包含 3 条消息和 1 张合成收据图片，不涉及真实人物。首次分析请求完成后，注入编辑目录冲突，让流程在后续模型请求前停止。清除测试标记后，通过与页面相同的续跑接口继续。

| 检查点 | 实际请求数 | 输入 token | 输出 token |
| --- | ---: | ---: | ---: |
| 注入本地故障后 | 1 | 1,511 | 4,068 |
| 续跑完成后 | 4 | 19,051 | 9,150 |
| 再次生成相同案例及续跑已完成任务 | 4 | 19,051 | 9,150 |

首次分析的尝试记录始终只有 1 条；后续 3 次请求分别用于提纲、成稿和审稿。4 次请求均有供应商返回的用量，无计费未知请求。输入中 8,448 token 被供应商记录为前缀缓存命中，这部分仍可能计费，不能与本地零请求复用混淆。以上数字包含模型返回的全部输出用量，不根据正文长度估算费用。

## 磁盘恢复：使用实际响应，禁止联网

`scripts/verify-cached-resume.py` 在独立进程、临时副本内执行，不修改原案例、运行或正在提供页面的服务，不需要 API 密钥。它同时禁止底层模型调用与 HTTP 请求，并验证恢复内容与原结果一致。

- 模拟最终发布前进程退出：仅凭磁盘检查点完成恢复，新增模型请求、网络请求和 token 均为 0。
- 模拟分析响应已收到、检查点尚未提交时退出：从原始 DeepSeek 响应重建检查点并完成恢复，新增请求与 token 均为 0。
- 两种情形都对原运行目录做前后文件哈希核对，确认原始数据未改变。

复验方式（使用当前流程版本已完成的运行编号）：

```bash
python scripts/verify-cached-resume.py <run_id>
python scripts/verify-cached-resume.py <run_id> --recover-raw
```

## 重试与结论边界

19 项检查点测试通过，包括 429/503 的有界重试、401/402/400 不盲重试、504/断线后要求确认、请求上限跨续跑保留、缓存损坏停止和重复提交互斥。HTTP 错误由受控测试模拟，没有为了测试而故意向真实接口发送失败请求。

本轮证实的是：**已有成功结果和完整已接收响应可以零新增请求恢复；失败不会迫使整个流程重新付费。** 无法证明供应商收到请求但客户端未收到响应时是否已经计费，此类情况继续保留“用量未知”并等待明确重试，不能承诺所有网络故障都零损耗。金额以供应商账单为准。

完整 137 项单元测试通过。合成报告通过桌面/手机布局、展开收起、引用跳转、原文搜索、图片放大和离线网页测试；浏览器阅读未产生外部网络请求。

## 实际材料发现的配置问题

首次带多张图片的实际分析触及单步 12,000 输出 token 上限：供应商返回 39,725 输入、12,000 输出，其中思考 12,000、正文 0。流程正确停止，只产生一次请求，没有自动盲重试，也没有可冒充成功结果的正文缓存。该次已发生用量单独保留，不从最终成本记录中删除。

原因是接口原先没有显式指定思考方式，而当前 DeepSeek 默认为高强度思考。[官方参数说明](https://api-docs.deepseek.com/guides/thinking_mode/)（2026-11-14 核对）。修复后明确默认 `thinking.type=disabled`；设置中可选低/高强度思考。思考方式纳入请求缓存指纹，避免不同参数共用结果。依然保留 12,000 单步上限、提纲、成稿与独立上下文原文审稿，没有通过无界提高输出限额掩盖问题。

用量额外展示供应商报告的 `reasoning_tokens`，它属于输出 token 的子集，不再次加到总量。新增检查覆盖思考参数实际传输、缓存身份、非法参数提前拒绝、修改方式保留同端点密钥，以及思考用量不重复累计。修复上线需要重启；旧进程中的临时密钥不被导出或转存。

## 后续实际流程与本地恢复

关闭深度思考后，首次分析返回正文，使用 39,701 输入、3,561 输出 token。发现一个完整消息哈希后多出一位十六进制字符，本地按精确完整哈希修正两个引用位置；没有模糊匹配或推断引用。该次分析只调用一次，后续续跑反复读取检查点。

实际成稿还出现可选图片字段的 `null`、用图片文件名代替消息编号，以及不能与转写逐字对应的精选引文。新增本地处理仅限：

- 可选图片/引文展示字段的 `null` 转为空字符串；正文、人物和证据等字段的缺失继续拒绝。
- 完整 ZIP 消息编号后仅多一位十六进制字符，且原编号精确存在时归一；其他错字、缺字、未知编号不猜测。
- 图片文件名与唯一一条材料精确对应时绑定；多条材料共用图片时不猜测。
- 不能逐字核对的可选精选引文框不展示，不编造替代引文；正文、原始材料与原文附录保留，仍必须审稿。
- 能从人物栏明确解析的拉丁显示名改为一致的角色代称；不猜测中文字符串是否为真实姓名，不声称全文或原图已经可安全外传。

每项处理均保留来源、修复记录与原始响应。恢复完整但因本地格式校验失败的响应，不需要再次请求模型。本次运行通过带原件备份与校验值的本地迁移，将修复应用到已有检查点；没有把原 API 响应改成“模型原本就这样输出”。通用处理已进入分析、编辑与响应恢复路径。当前空闲服务已热更新工作模块，密钥留在进程中，没有再次转存或填写。

## 最终结果：恢复通过，复杂材料自动稿未通过

复杂材料的自动稿经过两轮返修，仍存在时序、归因与身份信息问题，最终审稿要求继续修改。程序保留失败和所有候选稿，不冒充成功，不无限追加重写。再次提交相同案例返回同一失败任务，请求数与用量不变。

为了提供可用的阅读入口，本轮另生成一份**复用同一批输入此前已核对阅读稿的网页版**；正文未改写，仅在开头清楚标注来源与这次自动稿未通过的状态。它有独立运行及来源记录，不覆盖失败任务，也不称为本次 DeepSeek 自动生成成功。该网页本身新增模型请求为 0。实际材料网页通过桌面、手机、引用、图片放大、原文搜索与离线浏览器检查，未发起外部请求。

| 用量范围 | 实际请求 | 输入 token（含缓存命中） | 输出 token | 已记录输入缓存命中 |
| --- | ---: | ---: | ---: | ---: |
| 合成小样本及续跑 | 4 | 19,051 | 9,150 | 8,448 |
| 思考上限导致的失败 | 1 | 39,725 | 12,000 | 0 |
| 真实材料分析、编辑与返修 | 10 | 474,945 | 22,827 | 373,888 |
| 本轮合计 | 15 | 533,721 | 43,977 | 382,336 |

其中思考 token 共 17,556，已包含于输出总量。15 次请求都有供应商用量记录，无用量未知请求；“模型请求已返回”与“整份报告通过”是不同状态。服务端输入缓存仍可能计费。金额未与账户账单核对。本轮不足以证明复杂案例可以可靠全自动成稿，也不将人工核对稿的阅读质量算作 DeepSeek 自动流程成绩。
