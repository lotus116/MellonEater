# 标准阅读工作流：失败诊断与小样本验证

日期：2026-11-14。当前标准阅读为 `compact-v2`。本轮仅对完全虚构的小样本发起新请求，未再次处理真实群聊；没有导入旧稿或人工修改模型正文、响应缓存。

## 为什么此前花了大量 token 仍未完成

从本机失败记录可确认，旧流程的一轮真实多图任务发生 10 次请求，累计输入 474,945、输出 22,827 token，其中 373,888 输入 token 命中供应商缓存。10 次请求均带全部 15 张图片；各次输入约 4–5 万 token。缓存命中仍可能计费，不能等同免费。另一次开启高强度思考的尝试消耗 12,000 输出 token，均用于思考，未返回可用正文。

主要可修复问题在工作流：

- 原材料、原始分析、全篇候选稿和全部图片在多步反复传送；本地字数/格式问题也会触发全文改写。
- 审稿意见没有强制关联确切字段、候选原句和逐字证据，允许不稳定意见驱动新一轮改写；实际审稿出现反复意见和把 17:43 的“下午”表述当问题的情况。
- 修完内容后重新整篇审稿，缺少无效意见、无修改、重复候选的止损判断。
- 先前小样本验证证明了缓存恢复，未覆盖复杂叙事质量，不能据此推断复杂多图会一次成功。

因此不能把失败直接归因于模型能力不足。模型审稿本身也不稳定，新流程只能限制误判的后果，不能证明自动评判永远正确。本次审稿改用了低强度思考，因此新旧结果不是只改变工作流的受控模型能力实验。

## 新流程与边界

1. 本地整理完整原文、角色标签、消息/转发时间及来源不确定性；长编号映射成可逆短编号。删除导出噪声，不截断正文，不丢角色关系。
2. 有图时每批最多 4 张读取，记录逐字可见内容、图内原样时间与不确定处。观察结果不是独立证据；相同阶段的原始响应落盘。
3. 一次生成全新的结构化分析与阅读稿。成稿使用文字和图片观察，不重复发送图片；标准文字流程不再付费生成独立分析、提纲、全文三个版本。
4. 独立审稿使用候选稿和原材料，有图时看到原图。阻断意见必须指出具体字段、原句和原文依据；建议保留为未经验证的参考，不阻断或触发付费修改。
5. 仅修改诊断字段并复审，最多两轮。修改要匹配字段原值，拒绝无效路径、范围外修改、空修改和重复候选。无效审稿最多单独纠正一次，不立即改正文。
6. 审稿通过后确定性生成网页，PDF 单独检查。PDF 依赖或排版错误不会要求模型重写正文；不合格正文不发布为完成稿。

模型有时省略审稿路径的 `/reader` 前缀：只有能唯一定位且候选原句逐字匹配时本地补齐，并留存原路径；不模糊匹配、不修改原始响应。结构、证据、原文引用仍照常校验。本轮还修复了“非阻断建议也因路径不准阻止发布”的校验错误。

DeepSeek 阶段输出上限：读图/成稿各 6,000、审稿/局部修改各 4,000 token；审稿低强度思考，其余关闭。阶段设置覆盖全局偏好并纳入指纹。兼容 API 不发送 DeepSeek 专属思考字段；Codex 保留结构化输出，按传入图片顺序显式绑定来源编号。[DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)

每轮默认 20 次请求和已记录输入加输出 60,000 token 阈值；都计入重试与返修，重启不清零。阈值是发出下一请求前检查，单次在途请求可以越过，未知用量无法精确预扣，所以不是金额硬上限。页面和 CLI 支持显式提高阈值，不自动提高。

使用本机已配置的 DeepSeek 入口，返回模型名 `deepseek-flash`。预期答案留在测试文件，未进入模型请求。以下均为供应商返回的用量；思考 token 已含于输出，不另加，未知用量为 0。

| v1 初始时间/部分退款样本 | 2 | 5,106 | 3,992 | 完成；修复建议校验后仅本地缓存复验，无新增请求 |

| **总计（含初始试验及反例）** | **10** | **24,793** | **15,070** | **39,863 token；未核对金额账单** |

v2 三个新报告共 7 次请求、26,630 token。不能把小材料的 token 与旧版完整群聊直接相除，宣称同任务节省某个百分比。新稿不复用旧 reader；重复提交相同案例/设置返回原任务，实际新增请求为 0。反例重放也为 0 新请求。

人工对照原材料确认的核心断言：部分退款不等于全部结清；并行事件不合并为单一因果；图片新活动日为 11 月 15 日而非 14 日的转发时间，13 日 17:43 为通知发布时间；改期批准不等于活动已举办。

**阅读质量仍有缺口**：模型有时列出对主线无关紧要的未知问题（如取书具体地点），措辞偏谨慎；图文样本导语把参与者已自行更正误读，概括成“经转发者提醒后确认”，这个因果细节在原文中不充分，自动审稿没有拦下。没有手工修正文以掩盖问题。因此“完成/通过核心断言”不等于全文无语义瑕疵，更不代表复杂多图真实群聊已经验证通过。后续应先用针对性小片段检验因果归属与读图冲突，再决定是否扩大输入。

## 恢复、兼容和交互检查

- 在成稿响应落盘后注入本地写入失败：继续时复用成稿，只补后续审稿，总请求仍为 2。
- 独立进程复制任务，删除复制品最终报告，禁止所有模型/网络调用：从阶段缓存重新发布同一内容，新增请求和 token 均为 0，原任务字节不变。
- 独立复制品删除完成索引、保留原始响应并模拟中断：恢复原始响应后继续，新增模型/网络请求均为 0，原任务不变。
- 本地校验修复可 `resume --local-only`：缺阶段缓存就停，绝不因复验发新请求。缓存复用不依赖 API 密钥，其他模型配置须仍与指纹匹配。
- 浏览器检查桌面/手机、原文跳转、展开收起、原文搜索、图片放大和离线 HTML，未发现页面错误或外部请求。失败面板展示具体问题，不能继续的语义失败隐藏盲目重试按钮。
- 158 项离线测试通过，覆盖兼容请求结构、阶段参数缓存隔离、图片来源绑定、证据定位、受限局部修改、原始响应恢复、费用阈值、认证与隐私边界。兼容 API 和 Codex 本轮未做新付费实跑，不宣称所有服务均已实测兼容。
