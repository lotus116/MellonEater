# MVP 验收记录

日期：2026-11-14（香港时间）。这是单台 Mac 上的工程验收，不是正式研究结果，也不承诺不存在未发现的问题。

## 已验证

- 37 项自动检查：文字与 JSON 导入、转发父子关系及循环检测、来源保留、无效引用与伪造引文拒绝、报告正文要求、失败状态、四阶段顺序、重复任务保护、HTML 转义与图片内嵌、模型接口格式、密钥切换、本地 HTTP 访问限制、OCR 失败保留原图。
- 浏览器检查：案例载入、材料搜索、原文跳转、模型设置、文字导入、390 像素宽度显示；没有检测到页面脚本错误。
- 实际闭环：浏览器上传合成截图 → Apple Vision 本地 OCR → 保存案例 → 已登录 Codex 实际分析 → 刷新恢复进度 → 阅读版及原图查看 → PDF / HTML 导出。
- 真实用户材料：文字材料运行过 B1 单次分析和 B2 四阶段分析；补充原图后再次实际运行 B1，生成独立记录的阅读版。原始分析结果未被阅读版覆盖。
- 阅读版 PDF 使用嵌入中文字体，五页逐页渲染检查了正文、图片、标题及页码。生成结果只保留在本机。
- 可编辑安装构建通过；浏览器及真实调用记录保存在被 Git 忽略的本地目录。

## 小规模模型行为检查

同一合成案例以 B1 分别运行原版、身份变化、新增材料、删除材料，共四次真实调用。预期行为没有传给模型。

- 身份改成当事人后，主要金额及拒报事实判断保持；个别行为评价的限定强度有所变化，不能宣称完全不受身份影响。
- 新增当事人更正金额与承认未获同意后，报告更新为有条件的超预算判断，没有因此认定另一方拒付。
- 删除预算原始约定后，报告指出预算缺失，没有继续引用已删除的金额上限。
- 同源转述没有被当作两份独立佐证。

以上为助手逐条查看后的功能检查，没有独立人工标注、盲评或统计检验。不得据此声称 B2 优于 B1、模型无偏或项目研究假设成立。

## 发布与隐私

仅提交源码、文档、测试和明确标注的合成样例。真实材料、图片、OCR、模型请求与响应、报告、临时浏览器截图和密钥均在忽略目录中。发布前核对文件清单、聊天片段重合、个人路径和密钥特征；提交使用隐私邮箱。

本机保存不等于模型离线运行：选择 Codex 或云端 API 时，选定案例会发送给对应服务。当前程序仅监听本机，未部署公网服务。

## 阅读结构第二次调整

针对“主线不清、仍在逐段解释聊天”的反馈，新增事件主线字段：核心问题、阶段事件、该阶段带来的变化、先后顺序依据，以及支线在主线中的作用。阅读版先交代事件脉络，再展开关键转折；最多选取一张关键截图。已有旧结构仍可读取。

时间顺序标签必须从“时间戳可确认 / 相对顺序可确认 / 当事人回述 / 先后未确认”中选择，主线和支线必须有实际材料引用。标签与引用校验不证明因果成立，仍需核对；不允许为了讲顺故事补造时间或动机。旧阅读稿与调用文件在本机运行目录的 editions 子目录留档，结构化原始分析不被覆盖。

最终这一轮共 52 项自动检查通过，浏览器核对了五阶段主线、两条支线、材料跳转、手机宽度和 PDF / 离线 HTML 导出。真实阅读稿在模型生成后又经助手编辑与原图核对，保留生成稿和编辑说明；最终四页逐页检查。事实分析原始输出与本次编辑稿分别留存。

## 自动编辑工作流（本轮）

原先一次生成提示词不足以保证叙事质量。本轮增加独立保存的主线提纲、阅读稿、原文对照审稿、结构和版式检查，以及最多两轮自动返修。网页、CLI 和旧报告重编调用同一编辑器，skill 直接引用程序加载的规则文件。

66 项自动检查通过。新增覆盖四种分析入口均接入编辑、输入与原始分析不被覆盖、错误引用返修、语义审稿返修后重新审核、审稿“通过”标签不能覆盖未解决问题、排版溢出触发返修、达到上限不发布、事件分类不能遗漏，以及旧报告重编失败保留原版本。PDF 实际排版检查确认首页跨页能被程序检测；增加零碎尾页检测与来源说明整体排版，短尾页触发自动精简。skill 格式验证通过。

浏览器回归通过案例载入、材料跳转、导入、DeepSeek 设置表单及手机宽度检查，无页面脚本错误。DeepSeek 此轮仍仅验证适配与模拟接口，不声称已完成真实调用。

首轮新合成案例暴露了分析规范对阅读稿的影响：虽然引用合格，正文仍反复解释证据方法与假设性取证条件。修正后，编辑阶段使用独立叙事规则，不再继承逐条判断格式；排除事件的理由留在后台，不写入正文。保留该轮产物，没有手工改写来伪装自动成功。首轮并行事件案例达到两轮返修上限仍未通过，确实没有生成完成报告；原稿与失败反馈完整保留。

真实模型跨案例结果记录于本机 `data/private/editorial-eval-*.json`，对应输入、审稿与全部返修保留在运行目录。每份合成案例都来自仓库内明确标记的样例；没有再次发送真实用户聊天，也没有提交模型产物。自动审稿属于同一模型的新上下文检查，不是独立人工盲评。

### 最终实跑结果

使用本机已登录 Codex，模型 `gpt-6-astra`：

| 合成材料 | 自动行为与核对结果 |
| --- | --- |
| 读书会换场地被误传为取消 | 按消息时间处理乱序输入，排除无关聚餐；审稿发现逐消息复述后自动改成事件叙述，保留活动是否举办和更正是否收到的边界。 |
| 文件版本误会与独立团购延期 | 两件事分别成线，没有强串因果；区分评审已有完成报告、退款仍待回复，并分别保留各自状态截止点。 |
| 两条无日期借物消息 | 只生成两个阶段、零支线；不补造日期、逾期、永久遗失、赔偿或归还结果；正文自动压缩成一次协商的变化。 |

`editorial-v1.1` 的三次完整 B1 流程均经过一次自动返修后完成，各 6 次模型调用（1 次分析、5 次编辑）。新增尾页检查后，前两份再通过 `editorial-v1.2` 的统一旧稿重编入口，各 5 次编辑调用、一次自动返修，均从 3 页收为 2 页；第三份本来就是 2 页，以最终排版器复验。所有阅读稿均为模型原样输出，没有手改 JSON 或正文。

最终三个 PDF 都为 2 页，首页总览均为 1 页，末页内容占比约 82%、89%、70%；共六页渲染检查，无截断、重叠或零碎尾页。最终网页复验覆盖阅读稿、主线材料跳转、分析与编辑调用分列、PDF / HTML 导出、手机宽度，以及模拟编辑阶段切换和失败后按钮恢复。该进度测试不触发额外模型调用，可运行 `node scripts/editorial-browser-test.cjs <已完成的合成运行编号>`。

这些结果证明本次工程闭环与观察到的边界行为，不证明任意聊天都能一次生成理想文章。两轮返修上限仍可能触发明确失败；没有用放宽审稿标准来消除失败记录。

## 微信原生 ZIP 导入与媒体适配（2026-11-14）

80 项自动检查通过，其中新增 8 项原生 ZIP 检查与 6 项数据库媒体/凭据检查。覆盖按时间过滤、同批次附件绑定、跨批次同名图片隔离、缺图和歧义标记、多图父子关系、仅跳过完全相同 ZIP、保留同分钟重复文字、危险路径和符号链接拒绝、错误日期或格式不发布、过大材料分包、凭据通过文件描述符传入、权限不合格拒绝、媒体跨群与哈希不一致停止。

数据库测试包含实际运行签名的 GreenBubbles v0.10.0，读取人工构造的 SQLite 群记录，排除另一个群和时间窗外记录，通过消息编号解码 XOR 包装的合成 PNG，并验证字节一致；不只是模拟工具返回。没有真实微信凭据、群消息或图片参与该测试。普通环境未安装该可选工具时会明确跳过这项集成测试。

原生 ZIP 另通过命令行实际导入合成两条消息和一张图片，返回本机工作台链接，未启动模型分析。真实导出、真实群的三天完整性、当前微信构建兼容性仍等待用户配合，不以合成测试替代真实验收。

浏览器实际核对通过：原生 ZIP 合成案例显示两条材料；点击图片入口加载 120×80 的预期图像；手机宽度无横向溢出、无页面脚本错误。图片入口统一改为「查看图片」，不把缓存图或转换预览称为已验证原图。

## Codex 初始化权限故障（2026-11-14）

定位到本地服务由受限开发进程启动时，页面、ZIP 导入及普通接口都可工作，但其 Codex 子进程在初始化本机 app-server 时被系统拒绝（Operation not permitted）。该失败发生在分析启动前，原先统一提示检查登录和网络不准确。

修正为区分启动权限、登录、限额、网络、空结果与十分钟超时，只显示固定提示，不把原始日志或材料内容回显。使用正常终端权限启动本机 HTTP 服务；模型子进程仍是只读模式并禁用额外执行工具，没有通过关闭模型安全限制处理此故障。README 增加普通终端启动与保留材料后重试说明。

86 项自动检查通过，新增覆盖初始化权限错误的准确提示及日志隐私、超时归类。真实 Codex 的纯合成结构化连通测试通过；同样入口的实际案例重试已完成事件发现阶段，原始材料和旧失败记录均保留。本轮不以网页加载成功作为模型链路验证。
