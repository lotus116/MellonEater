# 实施计划：Mac MVP 与正式实验

更新：2026-11-14（香港时间）。

## 当前迭代

以两小时内可演示的闭环为目标：本地材料导入、事件发现、主张与证据清单、模型分析、原文核对、首份报告及测试。

平台调整只改变采集入口。Mac 先支持用户已有文字、JSON 与截图；Windows 微信自动历史获取保留为后续实际设备任务。研究主线仍是证据约束能否改善判断可靠性。

### 本轮完成条件

1. 一份真实材料能自动生成报告，结果明确记录模型和输入范围。
2. 关键判断可点击回到材料原文；图片保留原图，OCR 不确定性可见。
3. B0/B1/B2/A1 方法入口存在，失败与成功可区分，不以模板报告替代模型调用。
4. Codex 实际连通；DeepSeek 可切换配置并通过接口契约测试，真实连通待密钥。
5. 核心导入、引用、来源关系和失败处理有测试；桌面和手机宽度界面可用。
6. 本地 Git 管理并推送源码及合成样例，私人材料不进入远程仓库。

### 自动阅读稿工作流

将原先手动做的主线抽象、阶段合并、支线定位、结局校准与篇幅压缩固化为统一编辑器。所有分析方法完成后自动经过提纲、成稿、独立上下文审稿及最多两轮返修；程序检查来源与首页排版，失败保留分析但不发布未通过阅读稿。skill 与程序共用同一份规则，旧报告重编也调用相同入口。

用换场地误传取消、两个独立事件、无日期残缺片段验证迁移，不能只用原奖金案例。PDF 必须实际渲染检查。正式研究仍对独立保存的分析原稿评分，编辑调用用量单列，避免把额外审稿带来的变化归功于原分析方法。

## 后续十五天主线

- 1–3 天：授权真实案例、标注样例、Mac 采集可行性实测。
- 4–6 天：打磨证据流程与图文报告，完善采集适配；Windows 由用户配合测试。
- 7–9 天：按原始事件分开发 / 留出集，构造身份、新增和删除变体，冻结评分规则及提示。
- 10–12 天：正式对照、步骤匹配消融、人工核对与案例级统计。
- 13–15 天：演示、研究报告、失败分析与复现包。

20 个真实案例、8 开发 / 12 留出仍为计划。人工答案不进入模型输入。共享事件或来源的变体放在同一集合；不能把同案例变体视为独立样本。

正式实验需分别记录无依据事实、无依据归责、关键主张覆盖与恰当更新，不能用输出更长、引用更多、拒绝判断更多代替可靠性改善。

## 数据格式的后续扩展

当前 JSON 保留消息 ID、发言者、内层时间、转发时间、父容器、来源根及原图。后续采集器只负责生成该格式，不耦合分析模型。需要继续实现：按外层时间选择后完整保留转发内部内容、可靠去重及覆盖缺口、长材料分批检索、跨批事件合并、截图重叠关系检查。
