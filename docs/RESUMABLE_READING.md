# 可恢复的生成与交互阅读

## 使用

默认使用「标准阅读」B1。文字任务从成稿、审稿两次请求起步。图片按每批最多 4 张读取，成稿与审稿使用缓存里的读图记录。程序给文字字段分配编号，审稿返回逐字原句、替换内容和材料依据。每条修改独立验证，只应用一轮修改，再复核一次。局部复核保留全文证据，只检查改过的字段。仍有疑问时直接输出报告，并在正文前列出复核局限。每轮默认最多 20 次请求，已记录输入加输出 token 阈值为 60,000，可在页面设置。

可恢复的失败或重启后，打开原案例，点击「从已保存的步骤继续」。已完成的模型结果从本机读取；不会重付之前的步骤。相同材料、身份、模型、地址、规则和图片重复点击生成，会返回原任务。确实要重新分析时，勾选「明确新建一轮（重新计费）」。服务重启不会自动提交模型请求，临时 API 密钥需在设置中重新输入。

- 原始输入与任务指纹在 `data/runs/<id>/input.json`、`manifest.json`。
- 阶段结果按完整请求与实际图片哈希保存在 `.calls/<hash>/completed.json`。结果带完整性校验；缓存损坏会停下，不自动付费重建。
- 每次尝试保存在 `.calls/<hash>/attempt-*/`，包括原始响应、供应商用量和状态。先保存收到的响应，再校验；在收到完整 API 响应后进程意外退出，也可以恢复而无需重发。
- 任务进度写入 `job.json`，失败历史另存，不把失败改成成功。所有 JSON 通过私有临时文件原子替换，权限为 0600。
- 模型、端点、原始图片或规则变化时拒绝混用旧运行；重新填同一服务的密钥不破坏缓存。旧版没有指纹和完整调用记录的运行不宣称可安全续跑。

命令行：

```bash
python -m chigua.cli analyze <case_id> --method B1 --provider deepseek --model <model> --max-requests 20
python -m chigua.cli resume <run_id>
# 只有接受中断请求可能已计费时才确认重试：
python -m chigua.cli resume <run_id> --allow-uncertain
# 已达到请求上限时，明确追加额度：
python -m chigua.cli resume <run_id> --max-requests 25 --max-total-tokens 80000
# 修复本地校验后，仅复验已存响应；缺缓存就停，不发新请求：
python -m chigua.cli resume <run_id> --local-only
```

旧报告重编也复用同一输入、规则、模型的检查点：`python scripts/reader-edition.py <run_id>`；需要接受中断计费或明确新建时分别加 `--allow-uncertain`、`--force`。

## 重试与成本边界

429、500、502、503 最多自动尝试 3 次，使用退避并尊重秒数形式的 Retry-After；等待超过 30 秒时停止，保留进度。401、402、400、格式错误和输出截断不盲目自动重试。504、断线、超时及进程中断可能已被服务端计费，需确认才重试未完成阶段。截断、缓存损坏应先解决原因，继续按钮不会原样付费重放。

请求上限包含全部已开始的尝试，不因重启、继续或阶段返修而重置；已记录 token 达到阈值也会停止下一请求，但在途单次仍可能越过阈值，未知用量亦无法预扣；这不是金额保证。进程锁阻止重复提交。日志不保存 API 密钥；已有缓存不向其他服务转发。

用量从供应商响应统计，缓存复用不重复计入；记录输入、输出、服务端缓存命中及用量未知的请求数，不把未知当零。DeepSeek 的服务端前缀缓存只降低符合条件的输入成本，仍可能计费，也不保证每次命中。将稳定材料置于变化任务之前，使重复前缀有机会被复用；本地完整结果缓存才是跳过请求。

标准 B1 对 DeepSeek 使用分阶段设置：成稿/读图关闭深度思考，输出各最多 6,000 token；审稿及局部修改关闭思考，输出各最多 4,000 token。思考用量属于输出的子集。这些阶段设置覆盖页面上的全局思考偏好，完整参数纳入缓存指纹；B0/B2/A1 仍用全局设置和旧版单步预算。通用兼容 API 不发送 DeepSeek 专属参数，Codex 使用其已有结构化输出入口；这两种入口本次仅做离线兼容回归，没有新实跑质量结果。

语义返修耗尽、审稿定位仍不合法、核心结构错误会显示原因，隐藏原样继续按钮。本地修复可用 `--local-only` 复验已存输出：即使没有密钥也可读缓存，但模型和端点配置须与原指纹一致；缺缓存立即停止。纯建议不阻断报告，真正的事实错误仍须提供候选原句与逐字原文。服务端错误和审稿失败不再共用“再整篇重写一次”的路径。

参考：[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)、[错误码](https://api-docs.deepseek.com/quick_start/error_codes/)、[Chat Completions 的格式及用量](https://api-docs.deepseek.com/api/create-chat-completion/)。核对日期：2026-11-14。现已完成真实 DeepSeek 小样本及本地故障注入验证，详见 [实际调用记录](DEEPSEEK_LIVE_VALIDATION-2026-11-14.md)；金额未与账户账单核对。

## 同一份内容，多种阅读方式

模型输出结构化事件、人物、转折、原文编号及阅读稿；网页与 PDF 使用相同结果，不另请模型编写网页。展开、搜索、放大、切换视图、重新导出均不调用模型。

独立网页版提供概况与当前结果、角色卡、可展开的阶段线、章节、争议与反证、原文搜索、引用跳转、图片放大。图片与样式内嵌，保存 HTML 后可离线阅读，不含追踪或外部资源。材料中的文本转义后显示，脚本是固定的本地交互代码。新增争议卡片引用的材料也纳入网页原文附录。

网页版先交代起因和当前进展，关键转折可以直接扫读。点「打印 / 存为 PDF」会在打印时展开正文、引用原文与图片，打印结束后恢复阅读状态。原有独立 PDF 导出仍可从命令行使用。

组织方式参考 [NN/g 的重要信息前置原则](https://www.nngroup.com/articles/inverted-pyramid/?no_head=1)：先让只读开头的人抓住核心，再提供支持细节。这是从网页阅读研究推导出的产品设计方向，不代表已经对中文“吃瓜”读者做过用户实验。可视化仅表达材料中已有的关系与顺序，不补造心理、关系网络或确切时间。

当前已完成 DeepSeek 实际小样本和复杂多图案例验证：缓存恢复通过，但复杂案例的自动稿两轮返修后仍未通过语义审稿，已停止追加请求。当前可用的真实网页阅读版明确标注复用同批材料此前已核对的阅读稿，不把它当成本次 DeepSeek 自动成稿成绩。详细用量与限制见 [实际调用记录](DEEPSEEK_LIVE_VALIDATION-2026-11-14.md)。
