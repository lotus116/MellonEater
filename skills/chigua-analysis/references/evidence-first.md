第一步只核对材料，输出事件底稿。覆盖能解释反应的前情（具体分工、交付、承诺、决策或先前摩擦），再核对原话／动作、公开披露、回击、事后解释和收尾。材料里同一句话可能被多次转发；优先使用显示原场景、发言人与上下文最完整的版本。截图上传者、截图里说话的人、转述者和被谈论者分别处理。反问“为什么你让我……”不等于反过来要求对方做同一件事。原群发言、公开贴出、回击和后来解释各用独立记录；找不到时留空。对后续公开补贴旧记录，不能用补贴时刻给旧动作定时。

events 按有依据的相对顺序排列，通常 4–8 条。kind 可为 前情、原始言行、公开披露、回击、事后解释、其他。每一条必须用一段连续且逐字相同的 quote 核对这一次动作。text 是导出的文字，image 是截图转写。标题 label 用动作本身，action 说清说了什么或做了什么。actual_actor 写无身份信息的角色。直接文字消息 actual_actor 写该条消息的人的 P 编号；图内／回述中的 actor_quote 必须是原话前相邻的说话者标注，或回述引文中的明确主语。仅知道外层发布者，actual_actor 与 actor_quote 留空，或另写一条明确归属的当事人回述。不能把一张图的群名和另一张图的发言拼在一起。

scene 写 小群、公开群、群聊、私聊、其他、未知。文字要以本条原文内的场景词 scene_quote 核对，回述至少要能看到动作和场景词在同一段；截图优先通过该图自己的窗口标题或图像描述来核对，不填其他截图的标题。time_origin 与 time_quote 只写同一动作的实际时间或相对依据（消息时间、图内时间、原文所述时间、未知）；有相对顺序但日期未知时，basis 简短写明由哪句回述或截图上下文确定，无法确认则不要用叙述语气确定日期或顺序。

disputes 将涉及同一事实的相冲突说法并列，尤其注意不同人报告的具体金额、时长与范围。accounts 使用独立引文，直接消息的说话者由元数据获取；stance 保留该方的具体数字和口径，不能把归属省掉。limits 写能改变解读的缺口。不要把行为责任推迟到事实缺口全部消除。人物角色用 roles 把 P 号映射为中性匿名角色，无材料支持角色时用参与者，不把显示名当身份。
